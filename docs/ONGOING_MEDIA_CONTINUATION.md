# Prospective live-media history checkpoint

`ManifoldOngoingMediaPolicy::active_checkpoint_v1()` selects
`rusty.manifold.peer.ongoing_media_policy.v1` through the actual embedding
owner. Omission retains the finite contract and its existing capacities. This
selection changes storage/replay handling; it grants no capability, deadline,
platform effect or application duration policy.

The first candidate checkpoints concurrent renewal histories after sixteen
complete same-graph adoptions. The constant-size latest checkpoint retains the
first issue-time media/route/derivative ancestry, latest accepted baseline,
source history commitment, prior checkpoint digest and cumulative renewal
count. The suffix is bounded. Checkpoint sequence/count arithmetic is checked;
sequence one has no prior digest, and subsequent sequences require one.
Accepted authority revisions, clocks, current grants, identities and deadline
policies are never reset. The operation creates no resource and requires the
live Broker join and current graph; the product composition calls it only
after actual product adoption. Exact retry returns the retained checkpoint.

Both signed common-LAN contexts and their accepted receipts bind exact owner
revisions. Completed composition results may leave the bounded retry suffix,
but a prior signed proof cannot authorize a new use: a new mutation must join
an exact currently retained signed-session receipt, current signed topology,
unexpired authority and an advancing actual Broker clock. Changing an outer
request ID does not change the signed context or make it retained authority.
The current generic nonce/correlation and admission replay histories remain
intact. This version does not yet compact those histories.

`ManifoldOngoingMediaRestoreAnchor` is minted only from an actual live owner
validated against its live Broker. Its private fields, lack of Deserialize
and absence of a digest constructor prevent target JSON from minting restore
authority. It borrows the sealed live owner, preventing mutation during the
borrow, and seals the exact canonical snapshot, trust policy, provider epoch
and current Broker evidence digest. A historical seal cannot roll back after
the live Broker changes. Detached normal restore rejects ongoing snapshots; the
explicit ongoing restore requires the independently held anchor and the
current live Broker. A damaged target, stale seal or foreign owner rejects.
This is a same-process restore contract. Process-death restoration requires a
separate authenticated embedding-owner storage anchor; an exported hash or a
checksum stored beside an arbitrary target is insufficient.

This is an intermediate source candidate, **not a claim of operation until
human Stop**. Generic Broker/admission/reciprocal/Runtime Host audit, evidence
and replay capacities still apply. Renewals across later media lifetimes and
compaction of those generic histories require further owner work. Current
expiry/revocation/uncertain cleanup remains fail-closed. The existing drained
Broker epoch rollover keeps its drain requirement and is not used here.

Focused validation lives in the Quest consumer's real coupled-owner seam:
actual Ed25519/credential/session/admission/Broker/media/product transitions,
deterministic platform owner effects,67 renewals, multiple checkpoints,
original cleanup ancestry, exact/relabel replay refusal, same-process sealed
restore, partial-adoption retry and unchanged physical graph. The pure counter
overflow controls are in `ongoing_media.rs`. These host checks prove no
Android effect, uninterrupted video, process-death recovery or runtime
adoption. Products must explicitly select and qualify this candidate.
